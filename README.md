# 拾页 · 成长日志

把学习过程写成一本可以翻阅的书。设一个目标，写下一页，然后看见自己究竟走到哪里。

在线访问：https://fkakfjfwfi.github.io/shiye-journal/

## 它解决什么问题

多数打卡工具只统计「有没有记录」。但学习不是打卡：停几天再回来，未必是退步；天天写字，也可能只是在原地绕圈。

拾页比较的是**日志里写下的实际证据**——做了什么、产出了什么、理解到什么程度、卡在哪里——而不是连续天数。记录空白只被标记为空白，不会被判定为懈怠；证据不足时，分析会明确说「无法判断」。

## 主要功能

- **目标与章节**：把「想学会 Python」拆成可验证的里程碑。
- **日记与周志**：手写或导入 `.md` / `.txt`，内容自动留在本机草稿。
- **专注阅读器**：同一目标的记录形成目录，支持上一篇 / 下一篇、进度跳转，并记住每篇读到哪里。
- **分阶段成长分析**：提取学习证据 → 与同目标前序记录比较 → 给出下一步建议。
- **可续跑的分析任务**：每个阶段完成即保存。模型额度耗尽或中断时暂停，换模型后只续跑未完成的阶段，不重新生成已有结果。
- **私有文库**：手机号验证码登录，数据按用户隔离，仅本人可读写。

## 技术形态

纯静态前端，无构建步骤：

```
index.html   页面骨架与对话框
style.css    深色文库 + 浅色纸页的视觉系统
app.js       视图渲染、本地状态、交互与快捷键
cloud.js     认证、云数据库、模型调用与分析编排
```

云端使用 WorkBuddy 托管服务：短信验证码登录、PostgreSQL 数据表、流式模型调用。数据表 `journal_records` 启用行级安全策略，`owner_id` 默认为 `auth.uid()`，前端不提交该字段。

## 本地运行

任选一个静态服务器，例如：

```bash
python -m http.server 8765
```

然后访问 `http://127.0.0.1:8765`。

## 快捷键

- `Ctrl / ⌘ + J`：写一页
- `Ctrl / ⌘ + K`：进入文库搜索

阅读器的页面层级与交互节奏参考了开源项目 [light-novel-library_Wenku8_Android](https://github.com/MewX/light-novel-library_Wenku8_Android)（GPLv2）的设计思路，但未复制其代码；本站为独立实现，业务语义也完全不同。

分析功能需要登录并消耗模型额度，额度状态不由页面查询。
